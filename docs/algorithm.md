# 算法说明

## 这套算法做什么

一次古风气韵评测接收二十道题的答案，先得到五维气韵，再把它与每首歌曲的五维参数比较。距离较小的歌曲排在前面。

模拟诊断没有另一套歌曲推荐算法。它只是重复生成答案，多次调用同一个评测算法，然后统计排名出现的频率。

## 五个维度

数组下标和含义如下：

| 下标 | 正向名称 | 反向名称 |
| --- | --- | --- |
| `0` | 古典 | 现代 |
| `1` | 旁征博引 | 通俗晓畅 |
| `2` | 含蓄蕴藉 | 直抒胸臆 |
| `3` | 致密沉实 | 空灵飘逸 |
| `4` | 精心构架 | 行云流水 |

代码里的五维数组都使用这个顺序。新增歌曲或阅读报告时，不要交换位置。

## 题目选项如何计分

每个选项包含五个与计分有关的字段：

```js
{
  key: "A",
  mainAxis: 4,
  main: 11,
  subAxis: 0,
  sub: 9
}
```

含义是：

- `key`：答案键，当前为 A、B、C、D。
- `mainAxis`：主维度下标。
- `main`：加到主维度的分数。
- `subAxis`：副维度下标。
- `sub`：加到副维度的分数。

参与者选中这个答案后，算法执行：

```text
profile[mainAxis] += main
profile[subAxis] += sub
```

二十道题全部累计完成后，第一维“古典”还要做一次特殊换算：

```text
古典 = floor(sqrt(古典累计值) × 10)
```

`floor` 表示向下取整。其他四个维度不做这一步。

这条特殊规则会使均匀模拟中的古典均值与其他维度不同。看到第一维分布偏高或偏低时，先检查这条换算，不要把差异直接归因于歌曲参数。

## 参与者五维气韵如何拉伸

当前算法只在参与者的原始五维值计算完成后增加逐轴拉伸，用来放大各维度偏离聚集中心的程度。每个维度使用下面的公式：

```text
拉伸值 = clamp(中心值 + (原始值 - 中心值) × 增益 + 偏移, 0, 100)
```

`clamp` 表示把小于 `0` 的结果设为 `0`，把大于 `100` 的结果设为 `100`。最终结果保留两位小数。

| 维度 | 中心值 | 增益 | 偏移 |
| --- | ---: | ---: | ---: |
| 古典 | 70 | 1.6 | 6 |
| 旁征博引 | 50 | 1.6 | 0 |
| 含蓄蕴藉 | 50 | 1.6 | 0 |
| 致密沉实 | 50 | 1.6 | 0 |
| 精心构架 | 50 | 1.6 | 0 |

例如，原始五维值 `[40, 9, 0, 0, 0]` 拉伸后是 `[28, 0, 0, 0, 0]`。第二维到第五维的计算结果低于 `0`，因此被截断为 `0`。

歌曲参数不使用这套拉伸。`data.js` 以及浏览器本地覆盖中保存的五个数值就是歌曲的最终坐标，评测会直接用它们计算距离。调整歌曲参数时不需要预先换算，也不要为了抵消参与者拉伸而手工套用反向公式。

## 如何计算歌曲距离

参与者拉伸后的五维气韵记为：

```text
U = [u0, u1, u2, u3, u4]
```

一首歌曲未经拉伸的最终坐标记为：

```text
P = [p0, p1, p2, p3, p4]
```

算法使用欧氏距离：

```text
R = sqrt(
  (u0 - p0)² +
  (u1 - p1)² +
  (u2 - p2)² +
  (u3 - p3)² +
  (u4 - p4)²
)
```

可以把五维参数想成五维空间中的位置。两个位置越近，`R` 越小，歌曲越契合。

## 相似度如何显示

相似度公式是：

```text
similarity = min(100000 / R², 100)
```

结果保留两位小数。距离小于 `0.01` 时直接返回 `100`，避免除以接近零的数。

例子：

```text
R = 50
similarity = 100000 / 2500 = 40
```

页面显示的整数百分比是相似度四舍五入后的结果。它用于娱乐性展示，不是统计学概率。

## 歌曲如何排序

排序步骤不能随意交换：

1. 先计算未取整的欧氏距离。
2. 把每首歌曲的距离保留两位小数。
3. 按这个两位小数距离从小到大排序。
4. 两首歌曲的两位小数距离相同时，按中文歌曲名称排序。
5. 普通页面取前五首。

注意：排序使用保留两位后的距离，不是原始距离。这是当前线上行为，测试已经锁定。若要改成按原始距离排序，应视为算法变更，更新 `algorithmVersion` 并重新评估分布。

## evaluate 的输入输出

创建评测：

```js
const assessment = createAssessment({ questions, songs });
```

执行评测：

```js
const result = assessment.evaluate(answers, { topN: 5 });
```

`answers` 必须与题目数量相同，每一项都是该题存在的选项键。缺少答案或使用未知键会抛出错误。

返回结构示意，数字不代表生产数据的固定基线：

```js
{
  profile: [80, 60, 50, 40, 20],
  matches: [
    {
      name: "示例歌曲",
      distance: 50,
      similarity: 40,
      displayPercent: 40
    }
  ]
}
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `profile` | 拉伸后的五维气韵，顺序固定 |
| `distance` | 保留两位小数的欧氏距离 |
| `similarity` | 保留两位小数的展示相似度 |
| `displayPercent` | 页面使用的整数百分比 |

## 均匀模拟评测

均匀模拟中的每一道题独立抽取 A、B、C、D，每个选项概率相同。它回答的是下面这个问题：

> 如果答案空间被均匀抽样，当前计分和歌曲参数会产生怎样的排名分布？

它不代表真实参与者。真实用户可能更常选择某些选项，题目之间也可能有关联。因此文档和页面使用“第一契合率”“前五入选率”，不使用“真实推荐概率”。

二十道四选一题共有：

```text
4²⁰ = 1,099,511,627,776
```

种答案组合。页面只抽取其中一部分，所以 1,000、10,000、100,000 或 1,000,000 次结果都是抽样频率，不是穷举结果。

## 固定种子和随机数

相同种子、随机算法版本和样本数必须生成相同答案。

处理过程：

1. 如果种子只包含数字，把它转换成无符号 32 位整数。
2. 其他文本通过 FNV-1a 转换成无符号 32 位整数。
3. 使用 `mulberry32-v1` 生成 `[0, 1)` 范围内的伪随机数。
4. 每道题用随机数选择一个等概率选项。

伪随机数不是安全随机数，这里也不需要安全随机数。它的用途是复现同一批测试数据。

## 模拟汇总内容

每次完整运行会统计：

- 每首歌曲成为第一契合歌曲的次数和频率。
- 每首歌曲进入前五的次数和频率。
- 第一名距离并列的样本数。
- 第五名与第六名距离并列的样本数。
- 每个维度的均值、最小值、最大值和十档直方图。

直方图区间为 `0–9`、`10–19`，依次到 `90–100`。值 `100` 放入最后一档。

第一契合率：

```text
firstRate = firstCount / sampleCount × 100
```

前五入选率：

```text
topFiveRate = topFiveCount / sampleCount × 100
```

两个频率都保留两位小数。若有 100 首歌曲且每次都返回五首，所有歌曲的 `firstCount` 总和应等于样本数，`topFiveCount` 总和应等于样本数的五倍。浏览器集成测试会检查这个守恒关系。

## 并列是什么意思

算法先把距离保留两位，再判断并列。因此两首歌曲的原始距离略有差异，只要保留两位后相同，也会被统计为并列。

主统计仍使用当前排序结果。并列时不会随机分配名次，也不会让歌曲共享第一名；中文名称排序决定最终顺序。报告单独记录并列次数，方便判断名称排序对分布的影响。

## 题目指纹和参数快照

报告的 `questionFingerprint` 使用题目选项键、主副维度和权重计算。只要这些计分字段变化，指纹就会变化。题目文案变化但计分字段不变时，指纹保持不变。

`songSnapshot` 保存本次使用的全部歌曲参数。比较两份报告前，检查：

- `algorithmVersion`
- `randomVersion`
- `seed`
- `sampleCount`
- `questionFingerprint`
- `songSnapshot`

这些字段不一致时，结果变化不一定来自算法。

## 什么时候更新版本

修改下面任一内容时，更新 `algorithmVersion`：

- 选项计分解释方式。
- 第一维特殊换算。
- 参与者逐轴拉伸的中心值、增益、偏移或截断方式。
- 歌曲参数是否参与拉伸。
- 距离公式。
- 相似度公式。
- 距离取整或歌曲排序规则。

不要手工修改多个测试里的版本和输出。正式批准变化时运行：

```powershell
npm run algorithm:update-baseline -- <新版本>
```

命令会更新 `assessment.js` 和唯一算法基线，但不会修改本页的公式说明。开发者仍需检查差异，并按实际规则更新文档。

修改页面样式、按钮文字、图表布局或下载文件名时，不更新算法版本。

CSV 或 JSON 字段结构发生不兼容变化时，更新 `schema_version`。详细约定见 [`ADR-0001`](./adr/0001-versioned-simulation-artifacts.md)。
